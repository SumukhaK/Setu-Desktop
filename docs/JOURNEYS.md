# Setu user journeys

This is the canonical journey specification for [Setu Desktop](https://github.com/SumukhaK/Setu-Desktop) and [Setu Android](https://github.com/SumukhaK/Setu-mobile). The baseline is Setu SDK **v1.0.1** at [d6335c6](https://github.com/SumukhaK/Setu/commit/d6335c67a977f7ef6c09e9959a31069ee79e0c4b). The HTML wireframes use deterministic fixtures. Rows marked **Integration** describe application work. Rows marked **SDK or service gap** require a capability to be built or verified before release.

## J1 · Choose a workspace

- **Solo.** Both apps start locally without an account. On Android, start hosting after readiness checks. On desktop, pair by code or select a locally paired device. The code has four digits, a hyphen, and six digits. Accept ten digits and format after the fourth digit, preserving leading zeroes. Validate pasted text. The phone rotates its code after successful pairing or three failed PAKE attempts that reach the phone. A stale code prompts the developer to read the current code on the phone. Successful pairing automatically pins both sides. [Device pairing and authorization](https://github.com/SumukhaK/Setu/blob/d6335c6/core/internal/engine/device.go#L177-L284) · [Desktop pairing](https://github.com/SumukhaK/Setu/blob/d6335c6/core/internal/engine/connect.go#L107-L160)
- **Corporate desktop.** Show the organization's configuration and an SSO action. **Integration.** The app opens the system browser for OIDC with Authorization Code and PKCE. After verified organization sign-in, the organization's issuer returns a Setu-compatible EdDSA JWT bound to the daemon's public key through `cnf.key`. `identity.public_key` reads the SDK identity and does not issue a token. The shipped identity uses a local file-backed Ed25519 key. A hardware-backed signer and custody guarantee require an adapter or SDK change. Corporate access also depends on enrollment, relay policy, and device grants. Keep OIDC tokens, Setu JWTs, and the daemon IPC secret separate. [JWT contract](https://github.com/SumukhaK/Setu/blob/d6335c6/core/internal/engine/corporate.go#L63-L139) · [Key storage](https://github.com/SumukhaK/Setu/blob/d6335c6/core/internal/engine/util.go#L35)
- **Corporate Android.** EMM supplies `relay_url`, `enroll_token`, `policy_json`, and an optional `relay_pin`. When an enrollment token first arrives, show **Your organization now manages this device** once per enrollment. Then show **Waiting for IT policy configuration** for missing required policy, or the restricted screen if device management disallows debugging. No pairing code is available in Corporate. **Integration.** Treat known enterprise provisioning with incomplete settings as Corporate and fail closed. Apply restrictions on a configuration change before starting or restarting the agent. Isolate cached Solo state from managed hosting and do not fall back to a Solo relay. Desktop mode guidance is informational. The managed Android host and corporate relay enforce policy. [Managed configuration merge](https://github.com/SumukhaK/Setu/blob/d6335c6/android/agent-protocol/src/main/kotlin/dev/genadb/sdk/AgentProtocol.kt#L14-L55) · [Android service restart on policy change](https://github.com/SumukhaK/Setu/blob/d6335c6/android/app/src/main/kotlin/dev/genadb/companion/AgentService.kt#L39-L50)

## J2 · Prepare the phone

| Condition | Guide and readiness gate | Recovery |
| --- | --- | --- |
| Android 11+ on Wi-Fi | Enable Developer options, then Wireless debugging. Use Android’s temporary **Pair device with pairing code** sheet for the system six-digit code and its port. Pair once for the developer computer's ADB key, then attach through the separate debugging connection endpoint. | If the system pairing sheet closes or the port changes, reopen it and use the new values. Help the tester find **Build number** or the OEM equivalent. Recheck on returning from Settings. |
| Android 10 or cellular-only | On an approved device and trusted setup network, authorize USB debugging on a locally connected computer, then use `adb tcpip 5555` over USB. Verify the phone-side endpoint and relay reachability before unplugging. Use Setu's encrypted relay for remote access. Android may separately ask to authorize the developer's ADB key on the phone. | Recheck following reboot, an adbd restart, or an OEM setting change. If the device cannot support the fallback, stop and contact IT or use supported Wi-Fi. Legacy adbd may listen on network interfaces. Avoid public exposure, forwarding port 5555, or using untrusted networks. Stop the host and restore USB debugging mode when the authorized task ends. |
| Android 13+ | Check `POST_NOTIFICATIONS` and explain the foreground notification before asking. Denial can leave foreground hosting running, with a reduced notification experience and an in-app **Stop hosting** action. | Offer **Open notification settings** and recheck. Configure the ongoing service notification with `VISIBILITY_SECRET` and omit pairing codes and secrets from all notification variants. |
| Battery and OEM policies | Check `PowerManager.isIgnoringBatteryOptimizations` and offer system battery settings. Xiaomi MIUI/HyperOS uses Autostart and battery **No restrictions** where available. Samsung uses **Never sleeping apps**. ColorOS can expose per-app auto-launch and background activity. Resolve known vendor destinations before opening them and fall back to system app settings and manual instructions. | Treat OEM switches that cannot be read programmatically as unknown or tester-confirmed. If MIUI returns `INSTALL_FAILED_USER_RESTRICTED`, explain **Install via USB** and **USB debugging (Security settings)** where present and approved by IT. This is install recovery, separate from host readiness. |

**SDK or service gap.** v1.0.1's default adbd resolver discovers `_adb-tls-connect._tcp` and can fall back to phone loopback 5555. It does not discover the pairing endpoint or offer an `adb pair` RPC. The proposed desktop form collects the temporary system pairing port and six digits. An authenticated app adapter must allow only the enrolled or paired phone's temporary system pairing endpoint, give the desktop a separate local loopback forward for `adb pair`, and tear that forward down afterwards. The normal local ADB connection uses a different endpoint. Gate the automated flow until both endpoints and TLS authorization pass device tests. Treat both codes as ephemeral inputs and omit them from logs, diagnostics and notifications. The reference companion currently places the Solo code in its notification. Removing that text and setting secret visibility are native implementation requirements. ## J3 · Select a device and attach ADB

1. Select a paired device with `devices.list` in Solo, or a device ID from authorized organization configuration in Corporate. Show its exact `device_id` with an optional local nickname. The default `DeviceDiscoverer` lists local pins. Use **Last seen unknown** for static directories. **SDK or service gap.** A live presence provider such as a future authenticated `/v1/devices` must provide explicit presence and freshness. The v1.0.1 relay admin handler exposes only `/v1/revoke`. A failed attempt tells the user what happened to that attempt without guessing global presence. [Device discovery contract](https://github.com/SumukhaK/Setu/blob/d6335c6/core/pkg/genadb/interfaces.go#L30-L49) · [Relay routes](https://github.com/SumukhaK/Setu/blob/d6335c6/core/internal/engine/relay.go#L201-L244)
2. Desktop calls `session.connect` with a pairing code in Solo for first contact, or with the saved or granted `device_id`. Display the returned `adb_addr` on loopback. **Tunnel ready** identifies the authenticated preflight and local listener. The data path opens for a local ADB stream. Show actual **Direct LAN** or **Encrypted relay WSS** only with transport evidence. A verified audit session-start record can populate the path when audit is available. Preserve reported relay TCP or WS labels where configured and show **Path unknown** without a signal. The status strip omits RTT and geographic location. [Listener and per-stream setup](https://github.com/SumukhaK/Setu/blob/d6335c6/core/internal/engine/connect.go#L127-L203)
3. **Integration.** **Connect ADB** runs local Platform Tools against that exact loopback endpoint, then observes `adb devices` for its serial. Only `device` confirms **ADB attached**. `unauthorized` directs the user to phone authorization and `offline` prompts a retry. Keep listener readiness visible independently. Missing Platform Tools leads to Diagnostics. After attachment, Android Studio's device picker can choose that transport. [ADB CLI](https://developer.android.com/tools/adb)
4. On Android, `ConnectionState.Online` reports hosting, the device ID and optional adbd endpoint or warning. Visible **Stop hosting** stops the whole agent. `adbd_unreachable` prompts the user to restore the selected debugging method. **SDK or service gap.** Show a connected peer label and transport only when authenticated phone-side session events are available. No approval dialog or per-peer control in the v1.0.1 flow. [Android connection state](https://github.com/SumukhaK/Setu/blob/d6335c6/android/agent-protocol/src/main/kotlin/dev/genadb/sdk/Model.kt#L43-L75) · [Android agent event mapping](https://github.com/SumukhaK/Setu/blob/d6335c6/android/agent-protocol/src/main/kotlin/dev/genadb/sdk/AgentProtocol.kt#L68-L117)

## J4 · Recover from corporate denials

| Signal | Screen and recovery |
| --- | --- |
| `-32017` · No grant | **You don't have access to this device.** Request a grant from the IT administrator. Keep the device ID available to copy. |
| `-32018` · MDM blocked | **Debugging is restricted by your organization's device policy.** Contact IT. This is a reserved typed daemon mapping. The current Android host exposes `ConnectionState.Blocked`, and the v1.0.1 relay refusal mapper has no MDM-specific branch. Use the explicit status when supplied and keep generic denials generic. |
| `-32014` · Access revoked | **Your access was revoked by your administrator.** End the affected access state and stop automatic retries. A relay revocation may close an existing stream before a subsequent connect returns the typed reason. |
| `-32015` · Invalid token or `-32016` · Expired token | Sign in via SSO to recover. For expiry, say **Your corporate session expired. Sign in via SSO to resume.** Preserve unrelated working tunnels when refreshing credentials where the adapter supports it. v1.0.1 daemon starts with a fixed token from `--identity-file` and has no token-update RPC. The Go `AuthProvider` can refresh for future attempts. Existing streams and their rejoin path cannot be promised a live token swap. |
| Policy time cap | The relay enforces `max_session_seconds` on its relay splice. **SDK or service gap.** Show a warning at five minutes remaining only when an authoritative expiry for the current session is exposed. Avoid deriving a global deadline from configuration or a client-side stopwatch. |

## J5 · Background, reconnect and stop

- Minimize desktop to the system tray while keeping the daemon session alive. Relay's selected workspace and active session return on restore. Android keeps hosting in a foreground service. Its notification can expose **Stop hosting** without disclosing credentials. The app can stop any time from the host screen. Desktop **Disconnect** invokes `session.stop` for the selected session.
- The engine retries a broken underlying ADB stream for up to **90 seconds from detected path loss** and then closes that stream. The outer desktop SDK separately exposes `retrying`, `listening`, and `session_down`. Android's `Reconnecting` is agent lifecycle. None exposes the inner stream's `path_down` or `path_lost`. At baseline show public SDK state plus local ADB state. Show automatic retry only while the SDK or a product adapter is actually retrying. [Stream rejoin](https://github.com/SumukhaK/Setu/blob/d6335c6/core/internal/engine/tunnel.go#L25-L32) · [SDK events](https://github.com/SumukhaK/Setu/blob/d6335c6/core/pkg/genadb/events.go#L5-L15)
- **SDK or service gap.** Given an instrumented stream, hide transient loss for the first 10 seconds. For a continuous loss from 10 through 90 seconds, show a calm amber holding banner. Say the debugger stays attached only while attachment is observable. After the rejoin window, indicate the phone is unreachable and ADB will need to reattach. If an outer retry is active, say so. Otherwise offer **Reconnect**. Clear stale banners on recovery, stop or terminal policy errors. Use a monotonic clock and no countdown.
- In Solo, **Forget device** invokes `devices.forget` and deletes the local saved relationship. It does not remove the desktop key from the phone. For active access use **Disconnect** or **Stop hosting**. In Corporate, the administrator revokes access via the relay. An application offering corporate sign-out must clear its own tokens and explicitly decide whether to end its sessions. [Daemon session and local forget methods](https://github.com/SumukhaK/Setu/blob/d6335c6/core/internal/daemon/daemon.go#L335-L390) · [Relay revocation](https://github.com/SumukhaK/Setu/blob/d6335c6/core/internal/engine/relay.go#L201-L244)

## J6 · Verify audit integrity and run diagnostics

- **This Computer's Audit Log.** Call `audit.verify` on entry. Show **Verified** when `valid` is true and `anchor=verified`. Show **Unverified** for missing anchor, absent verification key, disabled log, or unavailable verification. Show **Tampered** when a returned chain fails verification or its anchor is invalid. Display warnings, broken record index and problem where the SDK returns them. Mark tampered exports accordingly if the report generator still allows export. Organization aggregation is handled by the central SIEM or webhook collector.
- Show **Operation-level** for visible classic ADB, **Session-level** for opaque Android ADB TLS, or unknown/mixed coverage if the source does not identify it. The relay transport and the Android ADB protocol are separate. **Export** calls `audit.report` for JSON, CSV or HTML with optional RFC 3339 date bounds. Save the generated report. The prototype previews these responses using fixtures. [Daemon audit methods](https://github.com/SumukhaK/Setu/blob/d6335c6/core/internal/daemon/daemon.go#L401-L445) · [Verifier](https://github.com/SumukhaK/Setu/blob/d6335c6/core/pkg/genadb/audit/anchor.go#L289-L359) · [Audit coverage](https://github.com/SumukhaK/Setu/blob/d6335c6/README.md#audit-and-reports)
- **Diagnostics.** Run the real `doctor` RPC and render status, detail and fix hint for `adb`, `state`, `paired_devices`, `proxy_env`, `relay_dns`, `relay_reach` and `audit_log`, including `relay` when relay checks are skipped. Allow unknown future checks. The `adb` check validates Platform Tools. Attachment still comes from the local ADB status adapter. Settings accepts **Custom relay URL**, **Relay certificate pin** and **Corporate HTTP proxy**. The pin is the hex SHA-256 of the WSS leaf certificate DER, with optional colons. Standard TLS verification still applies. Explicit HTTP CONNECT proxy applies to WS/WSS. Redact proxy credentials in diagnostic output. [Doctor checks](https://github.com/SumukhaK/Setu/blob/d6335c6/core/pkg/genadb/doctor.go#L67-L89) · [Transport and pin implementation](https://github.com/SumukhaK/Setu/blob/d6335c6/core/internal/engine/transport.go#L39-L50)

SDK-backed screens omit media capture, evidence uploads, inboxes, email/OTP, phone approval, phone per-peer disconnect, manual code renewal, and a phone trusted-access editor. The pre-audit video remains a historical artifact.

## Implementation acceptance tests

Write these first against fakes for daemon RPC, local ADB, EMM policy, Android Settings and the monotonic clock. Run the behaviors that depend on Android or the relay against physical devices or controlled test relays before enabling those capabilities.

| ID | Given and when | Then |
| --- | --- | --- |
| P01 | A fresh install opens Solo | Both apps enter local setup. No sign-in, approval, code timer, renewal, or opt-in pin control exists. |
| P02 | Enter or paste a ten-digit code with leading zeroes | The form displays NNNN-NNNNNN and passes that code to `session.connect`. Malformed letters, separators and partial inputs cannot submit. |
| P03 | First pairing succeeds, or a third counted PAKE failure occurs | Only the SDK event changes the phone code. Local pins are available after successful pairing. A remembered device uses `device_id`. |
| P04 | Android 11+ on Wi-Fi vs Android 10 or cellular-only | The guide picks the correct branch and requires the corresponding readiness. Permission or OEM limitations explain recovery. Policy forbids starting the USB fallback when required. |
| P05 | Wireless pairing adapter enabled; Android provides system code and pairing port | Both are validated. One authenticated temporary local forward is used for system pairing. Its teardown precedes using the regular ADB connection port. Codes never enter diagnostic output. |
| P06 | Android 13+ notification permission denied, or the device is locked | Hosting respects OS and policy, the in-app stop remains available, and no code appears in either notification variant. |
| P07 | EMM sends a token then a policy, with a separate debugging-blocked case | Managed transition appears once. Missing policy displays waiting. Blocked shows IT recovery. No unmanaged host starts in either state. |
| P08 | Static device directory, then fresh vs stale provider result | Static or stale data stays **Last seen unknown**. Only fresh provider data shows presence. Changing a nickname leaves the exact ID and grant unchanged. |
| P09 | `session.connect` returns loopback and local ADB transitions through absent, unauthorized, offline, and device | Listener status stays independent. Only the exact serial in state `device` displays **ADB attached**. Path comes from a trusted telemetry source. |
| P10 | Phone host is online; adbd stops; verified peer event is absent | UI distinguishes hosting from peer attachment, surfaces readiness recovery for the chosen path, and avoids inventing a peer name. Stop hosting stops the agent. |
| P11 | Each typed corporate error or unknown denial is returned | Render the matching recovery and never translate a generic denial into a guessed error. Revocation ends retries. |
| P12 | Credential refresh with healthy and broken active streams | New attempts use the fresh credential where supported. No unconditional daemon restart or seamless rejoin claim. Failing refresh routes to SSO. |
| P13 | An authoritative cap arrives and crosses five minutes remaining | Show one warning. With no expiry signal, no warning or guessed timer appears. |
| P14 | Instrumented losses recover at 9s or 50s, or cross 90s; a terminal denial arrives | 9s never flickers, 50s clears the holding banner on recovery, exhausted stream prompts reattach, and denial takes precedence. Out-of-order events for an old session cannot overwrite the current session. |
| P15 | Audit verifies, is missing a key, or returns invalid anchor/chain | Render the correct badge. JSON/CSV/HTML exports use SDK format, warnings stay visible and a file read error never reports Verified. |
| P16 | Doctor returns failures, skips or a future check | Include caller-visible detail and fix hints without logging a JWT, pairing code or proxy credentials. Route TLS and proxy settings through a configuration restart or new session without silently switching transport. |
| P17 | Minimize, restore, disconnect, or forget | Backgrounding preserves the session. Disconnect stops the selected ID. Forget removes the local pin without promising phone-side revocation. |
